# Анализ: разбор видео LUMOS, стандартный диспетчер Revit и боли пользователей

Этот документ — «почему плагин такой». Он сводит три источника:

1. видео‑демо плагина LUMOS (81 с, Revit 2024, 11 сцен);
2. что стандартный «Диспетчер проекта» Revit 2022 умеет, а чего нет (и что при этом позволяет API);
3. типичные жалобы и предложения пользователей (Revit Ideas, форумы Autodesk, обзоры сторонних аддонов).

---

## 1. Разбор видео LUMOS (сцена за сценой)

| # | Сцена | Что показано | Практика, которую забираем |
|---|-------|--------------|----------------------------|
| 01 | «Привычные папки. Прямо в Revit» | Панель **LUMOS Каталог** — библиотека семейств с диска, структура папок 1:1 как в Проводнике. | Панель живёт в **той же dock‑области**, что и стандартный диспетчер (вкладки «LUMOS Каталог / Диспетчер проекта LUMOS» рядом с «Диспетчер проекта»). |
| 02 | «Сначала посмотрите» | Карточки семейств с **превью**, версией Revit, пометками «Совпадает имя», «Revit 2026 — новее Revit». Hover показывает увеличенное превью с путём и размером. | Превью типоразмеров прямо в дереве + панель превью; подсказки с полной информацией; предупреждающие бейджи. |
| 03–04 | «Из каталога в проект», «Собирайте сцену» | Двойной клик → семейство загружается и сразу **переходит в размещение**; строка статуса «Запрошено размещение…». | Двойной клик по типоразмеру = `PostRequestForElementTypePlacement` (работает и для системных семейств: стены, перекрытия). |
| 05 | «Не обязательно по одному» | Чекбоксы у карточек, счётчик «Отмечено: 21», пакетная загрузка. | Multi‑select (Ctrl/Shift) + пакетные операции над всем выделением, «Выбрать все элементы папки». |
| 06 | «Виды проекта под рукой» | **Диспетчер LUMOS**: строка иконок‑разделов (виды, уровни, спецификации, листы, семейства, группы, связи…), поиск «Найти в проекте…», «Группы: по типу / категории», сортировка «А→Я», счётчики у групп, «Элементов: 1011». | Вкладки‑разделы, живой поиск, выбор группировки, сортировка, счётчики в папках, строка статуса. |
| 07–08 | «Создание листов» | Кнопка «+» открывает диалог: номер, имя, основная надпись (типоразмер). Лист появляется и открывается. | «+» → «Создать листы…» (с количеством, автоинкрементом номера, заполнителями). |
| 09 | «Сначала изменения. Затем подтверждение» | Внизу панели — **Применить / Отменить / ↺**: правки копятся, затем подтверждаются. | **Черновик**: inline‑переименование (F2), пакетное переименование и перенумерация складываются в черновик и применяются одной транзакцией (одно Undo). |
| 10 | «Перенумерация» | Диалог: Префикс / Начать с / Шаг / Цифр / Суффикс, таблица с чекбоксами, «Добавить в черновик». Результат: 1,2 → A001, A002. | Диалог перенумерации 1:1 + перестановка строк, безопасная двухпроходная смена номеров (A↔B не конфликтуют). |
| 11 | «Семейства и типоразмеры» | Раздел семейств: категории (системные помечены), превью или «Нет превью», разворачивание до типоразмеров. | Раздел «Семейства»: категории → семейства → типы, превью, счётчик экземпляров, «не используется». |

**Общие UX‑практики LUMOS, перенесённые в плагин**

* Одна панель, много разделов — вместо одного гигантского дерева.
* Поиск фильтрует дерево, а не «ищет следующее совпадение».
* Всё пакетное: выделил N элементов — операция применяется ко всем.
* Черновик изменений с явным «Применить».
* Иконка + короткий текст + серые бейджи в строке: масштаб, лист, кол‑во.
* Мини‑диалоги на 3–5 полей вместо мастеров.

## 2. Стандартный диспетчер Revit 2022: что есть, чего нет, что даёт API

| Возможность | Стандартный диспетчер | Project Browser+ |
|---|---|---|
| Дерево видов по «Организации диспетчера» | да | да — вкладка «Всё» и группировка «Как в Revit» через `BrowserOrganization.GetFolderItems` |
| Открыть / переименовать / дублировать / удалить / применить шаблон | да (по одному) | да, **пакетно**, с черновиком |
| Поиск | «Найти в дереве» (по одному совпадению) | живой фильтр по имени, номеру листа, шаблону, уровню, `id:123`, `*` = избранное |
| Группировки | только настройка «Организация диспетчера» (глобально) | по типу вида, уровню, шаблону, размещению на листе, дисциплине, стадии, масштабу, рабочему набору, префиксу имени, основной надписи, ревизии… — переключаются мгновенно |
| Быстрые фильтры | нет | «не на листах», «без шаблона», «открытые вкладки», «зависимые», «неиспользуемые семейства», «пустые листы»… |
| Какие виды **не размещены на листах** | не видно | бейдж «лист A‑101» / фильтр «не на листах» / группировка |
| Превью семейств | нет (только в Type Selector) | превью в дереве и панели превью (`ElementType.GetPreviewImage`) |
| Превью видов / легенд / листов | нет | по запросу через `Document.ExportImage` с кэшем на диске |
| Сколько экземпляров у типа / семейства | нет | счётчик и пометка «не используется» |
| Выделить все экземпляры | да (типоразмер) | да + для семейства целиком, группы, связи; «показать и приблизить» |
| Разместить типоразмер | drag&drop | двойной клик → режим размещения |
| Перенумерация листов | нет | диалог с префиксом/шагом/цифрами и безопасной сменой |
| Создать листы / планы по уровням | по одному через ленту | пакетно из панели |
| Легенду/спецификацию на много листов | drag&drop на каждый | «Разместить на листах…» с той же позицией, что на образце |
| Избранное / недавние / заметки / цветные метки | нет | да (хранится в %AppData%, модель не трогается — безопасно для worksharing) |
| Связи: статус, перезагрузить, выгрузить, открыть папку | только Manage Links | прямо в дереве |
| Уровни с отметками и видами | нет | вкладка «Уровни» |
| Экспорт списка | нет | буфер обмена / CSV |

Ограничения API, которые определили архитектуру:

* Изменять модель из модельной панели можно только через `ExternalEvent` → всё идёт через очередь `RevitTask`.
* `RegisterDockablePane` рассчитан на `OnStartup`; из команды может не сработать → есть fallback в плавающее окно.
* Drag&drop из своей панели в модель API не поддерживает → двойной клик → `PostRequestForElementTypePlacement`.
* Рендер вида (`ExportImage`) занимает секунды → превью видов только по запросу и с кэшем.

## 3. Частые жалобы и предложения пользователей → как закрыто

| Жалоба / идея (источник) | Решение в плагине |
|---|---|
| Табы в диспетчере, чтобы не скроллить гигантское дерево (самая голосуемая идея Revit Ideas, >1000 голосов) | 10 вкладок‑разделов |
| Поле фильтра/поиска, которое сужает дерево (Revit Ideas «Project Browser Search») | живой поиск с подсветкой и авто‑раскрытием |
| Пакетное переименование видов и листов (форум Autodesk, платные Ideate SheetManager / Magic Rename) | «Пакетное переименование…»: найти/заменить, regex, префикс/суффикс, нумерация, регистр, предпросмотр |
| Пакетная перенумерация листов | «Перенумеровать листы…» |
| Понять, какие виды не на листах и удалить мусор | фильтр «не на листах» + «Выбрать виды не на листах» + Del |
| Найти неиспользуемые семейства без Purge Unused (который удаляет всё подряд) | счётчик экземпляров, фильтр «неиспользуемые», «Выбрать неиспользуемые семейства» → Del |
| Не видно шаблона и масштаба вида без открытия свойств | бейджи и подсказки |
| Сложно найти активный вид в дереве | подсветка + «Показать активный вид», настройка «следовать за активным видом» |
| Легенду нужно ставить на десятки листов | «Разместить на листах…» |
| Нельзя поставить заметку/пометить вид «для проверки» | заметки и цветные метки (локально) |
| Слишком много открытых вкладок | «Закрыть неактивные вкладки», «закрывать остальные при открытии» |
| Задать «Разработал / Дата выпуска» на 50 листах | «Задать параметр…» для любого выделения |

## 4. Что ещё можно добавить (идеи на следующие итерации)

* Каталог семейств с диска (вторая панель LUMOS): обход папок, превью из RFA (`ExtractPartAtom` / thumbnail из OLE‑контейнера), пакетная загрузка.
* Drag&drop видов на лист внутри плагина (через `Viewport.Create` в точке курсора — API не даёт координаты drop, но можно ставить в центр и двигать).
* Сравнение имён видов с правилами именования (regex‑валидация, подсветка нарушений).
* Сохранённые наборы фильтров/группировок («Мои пресеты»).
* Синхронизация избранного через Extensible Storage (по желанию команды).
* Дерево рабочих наборов и переключение их видимости.
